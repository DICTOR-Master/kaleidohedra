# OEIS working page: standard layout (DICTO 23 Nov 2026)

One page per entry, published as a plain page with a Copy button on every field
(rule: text to copy = plain page). DICTO asks for changes to this layout as needed.

## 1. The sequence (supplied, checked)
- Working name and the shape or count it describes (one line, plain).
- Home paper and DOI.
- DATA line: the terms exactly as OEIS wants them (comma-separated, the first terms only, ≤ 260 characters).
- OFFSET.
- b-file: link to the file, its range, and the check that produced it.

## 2. Facts for the fields (supplied, checked; DICTO writes the sentences)
- FORMULA facts: each exact, with how it was checked (proof or exact computation, range).
- EXAMPLE facts: the small cases worked out (numbers only).
- PROG: programs (PARI and/or Python) that reproduce the DATA line, run and checked.
- MATHEMATICA, if supplied: run and checked.
- REFERENCES and LINKS: exact citations, DOIs, URLs (DICTO DOI label).
- CROSSREFS: related A-numbers, each checked to exist and fit.
- KEYWORD suggestions (nonn, easy, nice, ...) with one-word reasons.

## 3. Model entries to follow
- 2-3 existing A-numbers of the same kind, each with the field to look at and why.

## 4. DICTO's entry (he writes it from 1-3)
- Pasted back by DICTO when ready.

## 5. Verification (mine)
- Field by field: "verified" or "change: ... because ...". His wording kept; he makes the changes.

## 6. Status
- Submitted / proposed / editing / approved, with dates; editors' changes noted.
